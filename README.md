# AILAB 슬랙 채널 도우미 봇

> **인수인계를 받으셨다면 [`docs/HANDOVER.md`](docs/HANDOVER.md)부터 읽으세요.** 계정·설치·운영·문제 해결·검증하지 못한 항목·다음 할 일이 정리되어 있습니다.


## 1. 목적

동아리 슬랙의 공모전, 인공지능-소식, 코딩테스트 채널은 봇이 알림을 자동으로 올립니다. 지난 공고나 기사를 다시 찾으려면 스크롤을 오래 해야 하고, 알림에는 제목과 짧은 요약만 있어서 마감일, 시상 내역, 문제 풀이를 알려면 링크를 직접 열어야 합니다.

이 봇은 봇과의 DM에 `채널명`과 질문을 함께 보내면 해당 채널의 자료에서 근거를 찾아 출처 링크와 함께 답합니다. 코딩테스트 채널에서는 오늘의 문제를 읽고 풀이와 해설을 만들고, 입출력 예시로 자체 검증한 결과를 함께 알려줍니다.

## 2. 기능

입력 방식: 봇과의 DM에 질문을 보냅니다. `#채널명`을 붙이면 그 채널로 바로 가고, 붙이지 않아도 문장에 "공모전", "인공지능 소식", "코딩테스트" 같은 말이 있으면 채널을 추정합니다. 어느 채널인지 애매하면 되물어봅니다. 지원 채널은 아래 3개입니다.

아래 예시는 질문의 느낌을 보여주는 것이고, 같은 종류의 질문을 폭넓게 처리하는 것이 목표입니다.

### 공모전 (`#2-공모전`)
- **조건 검색**: "의학 데이터분석 공모전에 나가고 싶은데, 지금 모집 중인 게 있어?" → 모집 중인 공모전 중 주제가 맞는 것을 링크, 주최, 접수 기간, 참가 대상, 시상과 함께 안내
- **마감 임박**: "이번 주에 마감되는 공모전 알려줘"
- **개별 상세**: "OO 공모전 시상 내역이랑 참가 자격 알려줘"
- **자격 조건**: "대학생 개인으로 참가할 수 있는 AI 공모전 있어?"
- **신규 공고**: "이번 주에 새로 올라온 공모전은?"
- 기본은 모집 중인 공모전만 보여주고, 마감된 공모전은 요청할 때만 포함합니다.
- 마감일을 알 수 없는 공고는 모집 중이라고 단정하지 않고 "마감일 확인 필요"로 표시합니다.
- **수상작 분석**: "AI 공모전 대상 수상작들의 특징을 분석해줘", "OO 공모전 지난 수상작은?" → 미리 모아 둔 자료가 아니라 **질문할 때 웹 검색**으로 지난 수상작 자료를 찾아 읽고, 수상작 목록과 공통 특징(주제, 접근 방식, 사용 기술)을 근거 링크와 함께 정리합니다. 자료가 부족하면 분석하지 않고 "충분히 찾지 못했습니다"라고 답합니다.

### 인공지능-소식 (`#인공지능-소식`)
- **최근 이슈 정리**: "최근 가장 중요한 이슈 3가지만 정리해줘" → 기본 최근 7일의 기사를 주제별로 묶고, 여러 기사와 여러 매체가 다룬 주제와 최신 주제 순으로 뽑아 요약하고 기사 링크를 붙임. 답변에 선정 기준(기사 수, 매체 수, 최신성)을 한 줄로 밝힘.
- **개수와 기간 지정**: "이번 주 이슈 5개", "어제 소식 요약해줘"
- **주제 검색**: "RAG 관련 최근 소식", "OpenAI 동향"

### 코딩테스트 (`#2026-코딩테스트`)
- **오늘 문제 풀이**: "오늘의 프로그래머스 문제 답과 해설" → 문제 링크에서 본문을 읽고, Python 풀이와 해설을 만든 뒤 입출력 예시로 실행 검증
- **번호와 날짜 지정**: "181936번 풀이", "지난주 SWEA 문제 해설"
- **힌트만**: "답은 말고 힌트만 줘"

### 공통
- 모든 답변에 출처 링크를 붙이고, 근거가 없으면 "자료에서 찾지 못했습니다"라고 답합니다.
- 오래 걸리는 질문은 먼저 "읽는 중…" 메시지를 보내고, 단계가 바뀔 때마다(검색 중, 페이지 읽는 중 2/5, 풀이 검증 중 등) 같은 메시지를 갱신한 뒤, 완성되면 같은 스레드에 답을 올립니다.
- **후속 질문**: 답변이 달린 스레드에서 "두 번째 공고 시상 알려줘", "그 문제 힌트만"처럼 이어서 물을 수 있습니다. 스레드 밖의 새 DM은 새 질문으로 봅니다.

## 3. 사용 모델과 선택 근거

- 생성 모델: `gemma3:4b` (최종). 개발 중 GPU가 없는 노트북에서는 `gemma3:1b`를 CPU로 돌려 파이프라인이 동작하는지만 확인하고, 동작을 확인하면 `gemma3:4b`로 바꿉니다. 모델 이름은 설정값 한 곳에서만 바꿉니다.
- 임베딩 모델: `bge-m3` (한국어 자료가 많고 8K 컨텍스트를 지원)
- 근거:
  - 비용: 모든 모델이 로컬이라 호출 비용이 없고, 과제의 "상용 API 금지" 조건에도 맞습니다.
  - 보안: 모델 추론은 모두 로컬이라 슬랙 메시지와 시트 내용이 모델 제공사로 전송되지 않습니다. 단 PC 밖으로 나가는 것이 둘 있습니다. ① LangSmith 추적(프롬프트와 검색된 자료가 포함됨), ② 수상작 분석 때의 웹 검색어(공모전 이름과 분야만 전송, 슬랙 내용은 보내지 않음). 구조상 판단이며 측정한 값은 아닙니다.
  - VRAM: 계산식으로 계산하면 두 모델을 함께 올려도 8GB 안에 들어갑니다 (아래).
  - 4B로 정한 이유: 12B급은 8GB에서 경계라서 제외했고, 1B는 코딩테스트 풀이 같은 추론에는 부족할 것으로 보여 개발용으로만 씁니다. 품질과 속도는 구현 후 비교표로 측정해 추가합니다 `[확인 필요]`.
- VRAM 계산 (식: 가중치 + KV 캐시 + 오버헤드, `num_ctx` 4096 기준):
  - `gemma3:4b` (4.3B, Q4_K_M): 가중치 4.3 ÷ 2 × 1.15 ≈ 2.5GB(실제 파일은 비전 인코더 때문에 3.4GB) + KV 0.2~0.6GB + 오버헤드 0.7~1.0GB = **약 3.4~5.0GB**
  - `bge-m3` (567M, 파일 1.2GB): 0.567 × 16bit ÷ 8 ≈ 1.1GB + 오버헤드 0.7GB = **약 1.9~2.0GB**
  - 두 모델을 함께 올려도 합계 **약 5.3~7.0GB → 8GB 안에 들어감** (여유 최소 약 1.0GB). `num_ctx`를 8192로 올리면 약 7.6GB로 여유가 줄어서 4096을 유지합니다.
  - 어림값이며 화면 출력 등 다른 점유는 포함하지 않았습니다. GPU PC에서 `ollama ps`로 실측한 뒤 결과를 여기에 추가합니다 `[확인 필요]`.
- 참고: 코딩테스트 채널은 LLM이 도구를 고르는 방식이 아니라 코드가 채널로 라우팅해서 호출하므로, 도구 호출을 지원하지 않는 모델도 쓸 수 있습니다.

## 4. 사용 스택

- **LangChain**: 문서 로더, 텍스트 분할, 벡터스토어(Chroma 등), retriever, 체인
- **LangSmith** (필수): 아래 구간에 추적을 붙입니다. 로그인 코드는 추적에서 제외합니다.
  - 공모전과 인공지능-소식: 검색(retriever) 구간과 생성(LLM) 구간
  - 코딩테스트: 문제 읽기, 풀이 생성, 검증 구간
- **LangGraph**: 채널 라우팅, 되묻기(`interrupt`)와 스레드별 상태 저장(체크포인터, 후속 질문), 검증 실패 시 풀이를 재생성하는 반복, 수상작 분석의 재검색 반복, 진행 상황 스트리밍
- **슬랙**: `slack_bolt`, Socket Mode (입구와 출구는 슬랙), 과거 메시지 수집은 슬랙 API
- **수집 스크립트**: Google Apps Script(`app_script/`)가 링커리어, AI타임스·인공지능신문 RSS, 코딩 문제를 수집해 슬랙과 시트에 올립니다. `clasp`로 로컬에서 배포합니다.
- **구글 시트 읽기**: 시트 탭별 CSV 내보내기 URL을 `requests`로 내려받아 읽습니다 (읽기 전용, 별도 인증 코드 없음). URL은 `.env`에 둡니다.
- **Ollama**: 로컬 모델 실행 (상용 LLM API는 쓰지 않음)
- **웹 검색** (수상작 분석 전용): 한국어 검색 품질이 좋은 Naver 검색 API(무료 키)를 기본으로 하고, 키 없이 쓸 수 있는 자체 호스팅 SearXNG(Docker)를 대안으로 둡니다. LLM이 아닌 검색 서비스이며, 과제의 "상용 API 금지"가 LLM API만을 뜻하는지는 확인합니다 `[확인 필요]`.

## 5. 실행 환경

- **기준 환경은 WSL2(Ubuntu)입니다.** WSL 안에서 Ollama로 모델을 실행하고, 같은 환경에서 봇이 슬랙 Socket Mode로 연결됩니다. 코드 실행 검증(코딩테스트)은 WSL의 Docker로 격리합니다. 요건은 "VRAM 8GB 이하에서 동작"이며, 특정 GPU 모델에 의존하지 않고 3장의 수식 계산으로 판단합니다. 실제 GPU 모델은 미정입니다.
- **개발과 실측의 구분**: 현재 개발 노트북에는 GPU가 없어서 `gemma3:1b`를 CPU로 돌려 기능을 확인합니다. `gemma3:4b`의 실행 확인, `ollama ps` 실측, 속도 측정, LangSmith 추적 캡처는 8GB VRAM GPU가 있는 PC의 WSL2(NVIDIA 드라이버의 CUDA on WSL 사용)에서 합니다.
- **실행 방식**: 상시 실행은 하지 않습니다. 필요할 때 직접 봇을 실행하고, 실행 중일 때만 DM에 답합니다. 24시간 운영은 아래 "향후 계획"으로 남깁니다.
- **시작할 때 따라잡기**: 봇이 꺼져 있던 동안 올라온 슬랙 메시지와 시트 변경은 시작 직후 한 번 읽어 인덱스에 반영합니다.
- **클라우드 배포는 구현하지 않고 계획으로만 남깁니다.** 아래 "향후 계획"을 참고하세요.

## 6. 실행 방법

아래 명령과 파일 구조는 구현 전 초안이며(WSL2 Ubuntu 기준), 구현하면서 달라지면 이 문서를 고칩니다.

```
.
├─ app.py            # 슬랙 봇 실행 (Socket Mode)
├─ index.py          # 시트·슬랙 수집 → 분할 → 벡터스토어 구축/갱신
├─ app_script/       # 수집 스크립트(Google Apps Script, clasp로 배포, 웹훅은 스크립트 속성)
├─ requirements.txt
├─ .env              # 비밀값 (커밋 금지)
└─ src/              # 채널별 체인, 코딩테스트 풀이·검증, 수집기
```

1. 설치: `pip install -r requirements.txt`
2. 모델 받기: `ollama pull gemma3:1b` (개발용), `ollama pull gemma3:4b` (최종), `ollama pull bge-m3`
3. 루트 `.env`에 다음 변수를 만듭니다. 값은 절대 코드나 커밋에 넣지 않습니다.
   - `SLACK_BOT_TOKEN`, `SLACK_APP_TOKEN`
   - `LANGSMITH_API_KEY`, `LANGSMITH_TRACING`
   - `SWEA_ID`, `SWEA_PW` (SWEA 문제 읽기 전용 계정)
   - 수상작 분석: `SEARCH_PROVIDER`(`naver` 또는 `searxng`), `NAVER_CLIENT_ID`와 `NAVER_CLIENT_SECRET`(또는 `SEARXNG_URL`)
   - `GEN_MODEL` (`gemma3:1b` 또는 `gemma3:4b`), `EMBED_MODEL` (`bge-m3`)
   - 시트 CSV URL 5개: `SHEET_CSV_CONTEST`, `SHEET_CSV_NEWS_INAI`(인공지능신문), `SHEET_CSV_NEWS_AITIMES`, `SHEET_CSV_CODING_PROGRAMMERS`, `SHEET_CSV_CODING_SWEA`. 이 URL을 아는 사람은 시트를 읽을 수 있으므로 토큰처럼 취급합니다.
4. 데이터 인덱싱: `python index.py` (처음 한 번. 이후에는 봇이 시작할 때와 질문이 들어왔을 때 필요하면 자동으로 갱신)
5. 봇 실행: `python app.py`
6. 슬랙에서 봇에게 DM으로 `#채널명 질문`을 보냅니다.

### 테스트 채널로 시험하기 (운영 채널을 건드리지 않음)

질문은 DM으로 받으므로, 테스트 채널은 **슬랙에서 자료를 읽어 오는 경로**를 시험하는 데 씁니다. 비공개 채널이면 봇 스코프에 `groups:read`, `groups:history`가 필요합니다.

1. 슬랙에 테스트 채널(예: `봇-테스트`)을 만들고 봇을 초대합니다.
2. **`--test` 옵션**으로 실행합니다. `.env`를 고칠 필요가 없고, 옵션을 빼면 곧바로 운영 설정으로 돌아갑니다. 옵션을 주면 세 채널이 모두 `봇-테스트`(`TEST_CHANNEL_NAME`으로 변경 가능)로, 데이터 폴더가 `data-test/`로 바뀌어 운영 데이터와 섞이지 않습니다. 시작할 때 `🧪 테스트 모드: …` 안내가 출력됩니다.
3. 실제 형식의 메시지를 올립니다(운영 채널에는 올라가지 않도록 막혀 있고, 여러 번 실행해도 중복되지 않습니다).
   `python scripts/seed_test_channel.py` (`--dry-run`으로 내용만 확인, `--keep-dates`로 전송일 유지)
4. 수집과 봇을 테스트 설정으로 실행합니다.
   ```
   python index.py --test      # 테스트 채널에서 수집해 data-test/ 에 인덱싱
   python app.py --test        # 테스트 설정으로 봇 실행, DM으로 질문
   ```
   (`.env`에 `CHANNEL_NAME_ALL`, `BOT_DATA_DIR`을 직접 쓰는 방법도 있지만 `--test`를 권장합니다.)

**수집 스크립트(Apps Script) 시험**: 스크립트 속성에 `SLACK_WEBHOOK_URL_TEST`(테스트 채널 웹훅)를 한 번만 추가해 두고, 편집기의 함수 목록에서 `test…` 함수를 골라 실행합니다(`testFetchAndSendContestToSlack`, `testSendAiTimesNews`, `testSendDailyProgrammers`, `testSendDailySWEA`). 테스트 웹훅으로만 보내고 시트 기록·중복 방지 기록·`완료` 표시를 하지 않으며, 프로그래머스·SWEA는 요일과 관계없이 보냅니다. 속성을 바꿀 필요가 없고 평소 트리거는 기존 함수를 그대로 실행합니다. (스크립트 속성 `TEST_MODE=true`를 쓰면 트리거 실행까지 테스트 모드가 되므로 시험 후 꼭 지우세요.)

## 7. 알려진 한계

- 봇은 직접 실행한 동안에만 답합니다. 꺼져 있는 동안 보낸 질문은 처리하지 않으며, 실행 후 다시 보내야 합니다.
- 공모전은 수집 스크립트가 제목에 AI, 인공지능, 데이터가 들어간 공고만 모읍니다. 다른 제목의 공고는 자료에 없어서 봇이 찾지 못합니다.
- 공모전 시작일과 마감일은 수집 스크립트를 고친 뒤 쌓인 공고부터 채워지고, 그 이전 공고는 비어 있을 수 있습니다.
- 인공지능-소식의 "중요한 이슈"는 기사 수, 매체 수, 최신성으로 고른 것이지 객관적인 중요도가 아닙니다.
- GeekNews는 외부 슬랙 앱이 올리는 글이라 형식을 바꿀 수 없고, 형식이 바뀌면 파서를 고쳐야 합니다. 슬랙 요약이 중간에 잘린 글은 본문 전체가 아니라 일부만 근거로 씁니다.
- 수상작 분석은 웹 검색 결과를 읽고 정리한 것이라 공식 결과와 다를 수 있습니다. 수상작이 이미지나 PDF 포스터로만 공개된 경우는 읽지 못하고, 작은 모델의 요약 품질에 한계가 있어 근거 문장을 확인한 항목만 보여 줍니다.
- 코딩테스트 풀이는 입출력 예시로만 검증합니다. 예시를 통과해도 숨겨진 테스트의 통과는 보장하지 않고, 높은 레벨 문제는 작은 모델이 틀릴 수 있습니다.

## 8. 향후 계획 (구현 범위 밖)

클라우드 배포는 이번 과제에서 구현하지 않고, 검토한 내용만 계획으로 남깁니다.

- **목표**: PC를 켜 두지 않아도 봇이 24시간 답하도록 클라우드에 배포
- **검토 결과** (2026년 11월 기준, 조건은 수시로 바뀜)
  - GPU를 무료로 쓸 수 있는 클라우드는 찾지 못했습니다. CPU로 3B급 모델을 돌리면 응답이 느리고, 특히 코딩테스트 풀이와 재검증이 오래 걸립니다.
  - 카드 없이 쓸 수 있는 무료 호스팅은 메모리가 512MB 안팎이라 모델을 올릴 수 없습니다. 오래 켜 두는 프로세스가 잠드는 곳도 많아서 Socket Mode 봇과 맞지 않습니다.
  - Oracle Cloud Always Free(Arm CPU)와 Google Cloud(무료 체험 90일)는 결제 수단 등록이 필요합니다. Oracle은 유료 전환을 하지 않으면 청구되지 않지만 가입 실패와 용량 부족이 잦고, Google은 체험 종료 후 계속 쓰려면 유료 전환이 필요합니다.
- **상시 실행 (자동 시작과 재시작)**: 봇이 직접 실행할 때만 켜지는 한계를 없애기 위한 계획입니다.
  - WSL2의 systemd 서비스(`Restart=on-failure`)로 `python app.py`를 등록해 실패하면 다시 시작하게 합니다. WSL은 유휴 시 종료될 수 있어서 `wsl.conf`의 systemd 활성화와 Windows 로그온 때 WSL을 시작하는 작업(작업 스케줄러)을 함께 둡니다.
  - 시작할 때 Ollama가 실행 중인지 확인합니다.
  - 꺼져 있던 동안의 슬랙 메시지와 시트 변경은 이미 시작 시 따라잡기로 처리하므로 추가 작업이 필요 없습니다.
  - 상시 실행 PC는 아직 정하지 않았습니다 (현재 노트북은 GPU가 없음).
- **코딩 전용 모델 (보류)**: 코딩테스트 풀이에 코딩 특화 모델(예: `qwen2.5-coder:7b`, Q4 약 4.7GB)을 쓰면 정확도가 오를 수 있지만, 이번 범위에서는 `gemma3:4b` 단일 모델로 진행하고 나중에 검토합니다. 검토할 때의 방향은 아래와 같습니다.
  - 설정을 `GEN_MODEL`과 `CODE_MODEL`(비우면 `GEN_MODEL` 사용)로 분리
  - 코딩 시트의 `완료` 문제와 입출력 예시 자동 검증으로 후보(`gemma3:4b`, `qwen2.5-coder:3b/7b` 등)의 예시 통과율, 응답 시간, VRAM을 비교
  - 모델이 3개가 되므로 채널 전환 시 로딩 지연과 `bge-m3` 동시 적재 시 8GB 초과 여부를 `ollama ps`로 실측
- **실행한다면**: 소형 모델(1~3B)로 CPU에서 돌리고, 느린 코딩테스트 기능은 한계로 명시합니다. 과제 요건인 8GB VRAM 실행은 로컬 환경 기준으로 유지합니다.
